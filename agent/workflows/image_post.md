# 图文发布工作流（Image Post）

## 发布节奏（用户 2026-07-23 确认）

- **周一**：发正式长文（走 `agent/workflows/write_article.md` 完整流程，产出在 `output/<article-slug>/`）。
- **其他时间**：碰到新闻、热点、方法论，不写长文，改用**图文**（以图片为主的图片消息）快速发布。

## 平台模板硬约束（微信「图片消息」编辑器，type=10，2026-07-23 截图核实）

- **标题上限 20 字**（编辑器计数器实锤）。标题公式要在 20 字内装下"热词 + 钩子"，长文那套长标题直接搬会被截断。
- **图片就是正文**：编辑器没有正文区，只有图片序列 + 一段"描述信息"。读者的阅读动线是**滑图**，所以：
  * 每张图必须能独立被读懂（读者可能从中间开始滑）；
  * 第一张图承担封面 + 钩子职责（总览图/最大反差放第一张）；
  * 图片顺序就是叙事顺序。
- **描述信息**：简短配文，补上下文和使用指引，不承担主叙事（主叙事在图里）。
- 图片数量上限以编辑器实际为准（微信图片消息通常最多 20 张，未逐一验证，标注[待核实]）。

## 选题检查点（强制，与长文 Step 1 同源，2026-07-23 用户补充）

动手前必须先输出 **10 个图文候选选题**（含评分 + 时效标注 + 建议形态：卡组/转译/证据截图），**停下等用户选 1 个**，严禁直接开做。评估比长文多一条：**卡片化程度**——这个题的信息能不能自然长在图上（清单/流程/对比/时间线强，纯叙事弱）。

## 图数由内容决定，不套固定模板（用户 2026-07-23 划重点，最高优先级）

**核心原则：一张图能说清的，就用一张信息量足的大图；确实需要铺开的，才多图。图的数量服从内容的展开需要，不由"预设几张卡"决定。**

- **判断粒度的方法**：问"这块内容是一条连贯的线，还是若干并列的块？"
  * **连贯的线**（一条攻击链、一个因果推导、一段时间顺序）→ **一张大图**从头画到尾最清楚，拆成多张反而断气、让读者滑得累。
  * **若干并列的块**（N 个独立工具/N 种攻击手法/N 条互不依赖的要点）→ 才值得一块一张。
- **反面教材（本人踩过）**：把一个事件的完整攻击链（沙箱→零日→出网→盗凭证→RCE）硬拆成 3 张分步卡，纯注水——它本来就是一条线，一张竖向流程图看完最爽。
- **Vibe Coding 卡组能一阶段一张，是因为它是"工具图谱"**：7 个阶段各有独立工具和方法，天然并列。**不要把那套"1 总览 + N 分步"模板套到"讲一个事件"上**——事件的主体往往就是一张大图。
- **收尾的作者判断、互动引导，能放进"描述信息"就不单独占图**（描述区本来就承担这个）。
- 结果导向：宁可 2-3 张饱满的大图，不要 6-7 张注水卡；读者滑到第 5 张前极易流失。

## 视觉风格选择（生成 Prompt 前强制）

- 必须读取 `agent/workflows/image_post_styles.md`。
- 内容结构和图数确定后，从风格库推荐 **3 种风格**：默认推荐、偏亲切、偏传播各 1 种，并说明适用理由。
- 必须停下来等用户确认风格，再写整组最终 Prompt。
- 用户已经明确指定风格，或明确说“按默认风格”，可以跳过风格确认。
- 确认后，在 `img_outputs/<post-slug>/style-spec.md` 保存本组风格锁定规则。
- 每张图的 Prompt 必须完整重复风格锁定描述，不能只写“同上一张”。
- 风格只改变纹理、插图、图标和视觉气质；画布、字体可读性、标题位置、页码、安全边距和整组一致性仍遵守图文固定品牌层。

## 交付方式（默认先交付 Prompt，用户确认后再出图）

- **默认产出主体是 Prompt**：每张图先输出一份完整 Prompt 到 `prompts/`，用户逐张检查。
- 用户没有明确说“出图”时，严禁提前生成图片；用户确认 Prompt 并明确要求“出图”后，默认使用 Codex 内置出图能力。
- 每份 prompt 必须**单独可复制**（一图一文件，开头不写解释废话，用户拿去即用），按 img2 出图习惯写：自然语言版式描述 + 比例 + **图内文字逐字写明**。
- 全组图 prompt 必须锁定同一套视觉规范（同底色/同主色/同字体感/同卡片版式），保证滑图时是"一套图"。

## 已验证的两种图组形态（来自本号实发案例，2026-05）

**形态一：方法论卡组（自制图）**——例：《vibe coding 从灵感到上线，工具包拿去用》
- 结构：**1 张总览图**（全流程一屏看完，当封面钩子）+ **N 张分步卡**（每阶段一张，带 1/7 式进度标）。
- 单卡固定版式（可复用的模板骨架）：`序号 + 阶段名 + 一句话副标题` → `1 核心目标` → `2 推荐工具（logo+一句适合场景）` → `3 高效方法（三步箭头流）` → `4 输出结果` → `底部一句收束金句`。
- 配文套路：标题 + “这组图不只是用来看的”式**使用指引**（教读者把图喂给 AI 怎么用）+ 阶段清单 + 话题标签（#AI工作流 #AI工具 #本号 等）。

**形态二：外部好图转译（引用图）**——例：《Claude Code 已经不像 AI 了》
- X 上发现的优质信息图（如 Brij Kishore Pandey 的图）：翻译/重绘成中文版发布，**图内保留原作者署名**；配文做"为什么这张图值得看"的解读。
- **X 上找到的同类好图，先截图存进该图文文件夹的 `research/` 参考目录**（用 `agent/skills/twitter-capture/` 的路线截，同一红线：不许编辑内容后截）。research/ 里的图只做版式和内容参考，重绘时走洗稿红线：事实回一手信源核，版式可学，逐字搬运不行。

## 产出目录规则（强制，镜像 output/ 的规矩）

图文的所有产出统一放 `img_outputs/`，**每条图文一个专属文件夹**，严禁散放到根目录：

```
img_outputs/<post-slug>/
├── copy.md          # 标题（≤20字，附2-3个备选）+ 描述信息文案（含使用指引+话题标签）+ 图序说明
├── sources.md       # 新闻/事实来源链接、核对记录
├── style-spec.md    # 用户确认后的整组视觉规范、布局与禁止项
├── prompts/         # 每张图一份 prompt（01.md, 02.md...），与 images 同名，单独可复制
├── images/          # 用户出图后回存的成图（01.png, 02.png...）
└── research/        # X 等平台找到的参考图截图（原图存档，仅作参考）
```

## 内容红线（与长文同源，不因为快就放松）

- **图内文案规则（注意：与长文配图相反）**：图文形态里图就是正文，图内**必须**有标题、结构化信息和收束句——长文的"图内文案禁令"**不适用**于图文卡片（那条禁令的前提是正文已承载文字）。但仍然禁止：图内出现来源行水印式标语、与事实总账不一致的夸大表述。
- **persona.md 黑名单照旧**：配文和图内文字，A-E 类禁用词与"不是A，而是B"句式零容忍。
- **事实核对照旧**：新闻类图文引用的事实必须回一手信源核过，来源记入 `sources.md`；时效锚点用 48 小时内的。
- **截图真实红线照旧**：真实截图（含 research/ 参考图）只许裁边+留白，严禁编辑内容后再截。
- **引用图署名**：重绘外部信息图必须保留原作者名。
